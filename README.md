CodeMerge v2 — комплексный анализ инструмента
Общее назначение
CodeMerge — это одностраничное веб-приложение (полностью автономный HTML-файл с встроенными CSS и JavaScript, без серверной части и внешних зависимостей, за исключением шрифтов Google Fonts), которое решает узкую, но частую в разработке задачу: аккуратное внедрение изменённого или нового кода в существующий файл без переписывания его целиком вручную. Типичный сценарий использования — когда у разработчика есть большой исходный модуль (например, модуль формы или объекта в 1С, HTML-страница, CSS-файл стилей или JavaScript-модуль) и есть фрагмент кода с одной или несколькими изменёнными функциями, процедурами, правилами CSS или блоками разметки, который нужно точно "впаять" в исходник, заменив старые версии одноимённых блоков и добавив новые туда, где это уместно (например, в ту же именованную область в 1С). Инструмент специализируется на четырёх языках: 1С/BSL, HTML, CSS и JavaScript, и для каждого из них по-своему определяет, что считается "единицей замены" — процедуры и функции в 1С, объявления функций/классов/методов в JS, правила и at-правила в CSS, элементы с id или именованные блоки разметки (script, style, template, пользовательские теги) в HTML.

Помимо самого внедрения, инструмент включает второй, самостоятельный режим — генератор структуры проекта, который позволяет по текстовому дереву каталогов (вставленному вручную, импортированному из файла или сгенерированному через ИИ по словесному описанию) создать набор файлов с заготовками кода, отредактировать их во встроенном редакторе и либо скачать всё как ZIP-архив, либо передать отдельный файл в первый режим для дальнейшего внедрения правок.

Приложение построено как SPA с переключением между двумя крупными режимами через переключатель в шапке ("Внедрение" и "Создание проекта"), причём между ними организована содержательная связь: файл, созданный в конструкторе проекта, можно одним кликом отправить в редактор внедрения — либо как исходник, либо как патч.

Технологическая специфика. Всё приложение работает целиком на клиенте: разбор кода на методы, вычисление diff, синтаксическая подсветка, метрики сложности и валидация — всё реализовано собственными регулярными выражениями и алгоритмами без использования готовых библиотек парсинга или AST. Для распознавания строк, комментариев и литералов в каждом языке используется отдельная функция "маскировки" (masking), которая заменяет содержимое строк и комментариев пробелами, сохраняя длину текста и позиции символов — это позволяет регуляркам, ищущим структуру кода (заголовки процедур, скобки, теги), не путаться из-за текста внутри строковых литералов. Автосохранение состояния и настроек подключения к ИИ выполняется через localStorage браузера.

Режим «Внедрение» — основной рабочий экран
Это режим, открытый по умолчанию, и он представляет собой двухпанельный редактор кода с богатой обвязкой инструментов.

Шапка и статусная информация. В верхней части экрана расположены логотип, переключатель режимов, индикатор статуса операции (готово / в работе / ошибка, с цветовой и анимационной индикацией), значок автосохранения, показывающий, сохранены ли текущие изменения локально в браузере, а также кнопки отмены и повтора последнего действия, кнопка вызова справки по горячим клавишам, переключатель светлой/тёмной темы оформления и кнопка полной очистки обоих редакторов с подтверждением через модальное окно.

Панель инструментов (toolbar). Здесь сосредоточены главные действия: кнопка «Внедрить» (с горячей клавишей Ctrl+Enter), которая запускает основной алгоритм слияния кода; кнопка «Проверить», запускающая предварительный анализ на предмет ошибок и несоответствий перед реальным внедрением; кнопка «Черновой прогон» (dry-run), которая выполняет весь процесс внедрения и показывает результат и diff, но не записывает изменения в левый редактор — удобно для предварительного просмотра последствий. Далее идут кнопки копирования результата в буфер обмена, скачивания результата как файла с правильным расширением для выбранного языка, а также экспорта изменений в виде настоящего unified diff файла формата .patch с корректными хидерами хунков (@@ -начало,количество +начало,количество @@), который можно приложить к задаче или использовать для git apply. Здесь же расположен выбор языка (автоопределение или явный выбор одного из четырёх поддерживаемых языков), индикатор автоматически определённого языка, счётчик найденных в патче методов, кнопка открытия панели ИИ-инструментов, кнопка обмена содержимым левого и правого редакторов местами и кнопка открытия/закрытия боковой панели со списком методов.

Два редактора кода. Основную площадь экрана занимают два синхронизированных по стилю, но независимых текстовых редактора — левый (исходный код) и правый (патч-методы). Каждый редактор имеет собственную нумерацию строк, счётчики строк и размера в байтах, индикатор текущей позиции курсора в формате строка:столбец, кнопку открытия файла с диска, кнопку вставки из буфера обмена и кнопку поиска с заменой. Редакторы поддерживают drag-and-drop файлов прямо из файловой системы (с визуальным оверлеем при наведении), у каждого редактора реализована подсветка синтаксиса поверх текстового поля (отдельный визуальный слой, синхронизированный по скроллу с прозрачной textarea), а также умное поведение при вводе: автоматическое сохранение и увеличение отступа при переходе на новую строку после открывающих конструкций (для 1С — после Процедура/Если/Для/Пока/Попытка и аналогичных слов, для веб-языков — после открывающих скобок и открывающих HTML-тегов), автоматическое уменьшение отступа при вводе закрывающих слов 1С (КонецЕсли, Иначе и подобных), поддержка Tab и Shift+Tab для сдвига отступа как одной строки, так и всего выделенного блока, и комбинация Ctrl+/ для закомментирования/раскомментирования выделения синтаксисом, соответствующим текущему языку (// для 1С и JS, /* */ для CSS, для HTML).

Между двумя редакторами расположен перетаскиваемый вертикальный разделитель, позволяющий менять пропорции ширины панелей мышью.

Поиск и замена. По каждому редактору отдельно можно открыть панель "найти и заменить" (Ctrl+F/Ctrl+H), которая поддерживает учёт регистра, поиск только целых слов (реализовано через просмотры вместо стандартного \b, поскольку последний не работает с кириллицей) и поиск по регулярным выражениям с поддержкой групп захвата в замене. Панель показывает счётчик найденных совпадений вида "текущее/всего" и позволяет переходить между ними, а также заменять одно совпадение или все сразу.

Выборочное применение патча (patch selector). Если в правом редакторе обнаружено более одного блока для внедрения, под панелью инструментов патча автоматически появляется список этих блоков с чекбоксами и цветными метками (НОВЫЙ / ИЗМ. / без изменений), позволяющий отключить внедрение отдельных методов, оставив в силе только часть патча — это полезно, когда в буфер попал более крупный фрагмент кода, чем нужно было применить.

Боковая панель методов. Отдельная выдвижная панель слева от редакторов (Ctrl+M) отображает список всех обнаруженных единиц кода — как в исходном редакторе, так и в патче, между которыми можно переключаться вкладками. Панель включает: поиск по имени метода, сортировку по позиции в файле, по имени, по размеру (числу строк) или по цикломатической сложности; языкозависимые быстрые фильтры (например, для 1С — отдельно показать экспортные методы, клиентские, серверные или методы без описания; для JS — классы, методы, асинхронные функции; для CSS — at-правила, id-селекторы, пустые правила); блок статистики (общее число методов, суммарное и среднее число строк, размер самого крупного метода, число найденных дублирующихся имён); кнопку поиска дубликатов имён по всему файлу; групповые операции выбора (выбрать все, инвертировать выбор, снять выбор) и, наконец, кнопки массового удаления выбранных методов из редактора (с подтверждением) или их копирования в буфер обмена. У каждой строки списка есть иконка, обозначающая тип единицы (функция, процедура, асинхронная функция, класс), метаинформация о числе строк, значки для экспортных/асинхронных методов и предупреждение о высокой сложности или дублировании, а также кнопки быстрого копирования отдельного метода и перехода к нему прямо в редакторе (с выделением всего блока текста).

Панель результатов с вкладками. Нижняя часть экрана (с изменяемой по высоте областью через горизонтальный разделитель) содержит шесть вкладок, каждая со своим счётчиком-бейджем:

Вкладка «Лог» показывает пошаговый журнал последней операции внедрения или dry-run — какой язык распознан, сколько методов найдено в патче и в исходнике, что было заменено, что добавлено и куда, а также предупреждения о найденных после внедрения проблемах.

Вкладка «Сравнение» отображает построчный diff между старой и новой версией каждого изменённого или добавленного блока. Реализованы два режима отображения — единый (unified, построчно один под другим со знаками + и -) и рядом (side-by-side, две колонки), а также подсветка изменений на уровне отдельных слов внутри строки (например, если изменилось только одно имя переменной в строке, будет подсвечено только оно, а не вся строка). Каждый изменённый блок можно свернуть или развернуть кликом по заголовку, а результат сравнения можно скопировать как текст для приложения к задаче.

Вкладка «Результат» показывает итоговый код целиком с подсветкой синтаксиса — то, что получится после применения патча, до того как эти изменения (по желанию) будут перенесены обратно в левый редактор кнопкой «В исходник».

Вкладка «Проверки» отображает результаты валидации — списком карточек с уровнями серьёзности (ошибка, предупреждение, информация, всё в порядке), каждая с заголовком и развёрнутым описанием проблемы; клик по карточке, где упомянуто конкретное имя метода, переносит курсор прямо к этому блоку в соответствующем редакторе.

Вкладка «Метрики» показывает количественную сводку по коду: число строк кода без учёта комментариев, процент комментариев, число методов в исходнике и патче, среднюю и максимальную цикломатическую сложность (для CSS вместо неё используется "вес селектора", для HTML — глубина вложенности), число найденных групп дубликатов, таблицу всех методов с их размером и сложностью (кликабельную для перехода к методу), а также блок специфичных для языка показателей — например, для 1С это число экспортных методов, методов без описания, число областей #Область, запросов, блоков Попытка и соотношение клиентских/серверных методов; для JS — число классов, методов классов, асинхронных функций, обращений к DOM и вызовов console; для HTML — число элементов, элементов с id, скриптов/стилей, обработчиков on*; для CSS — число правил, объявлений, медиазапросов, CSS-переменных и вхождений !important.

Вкладка «История» хранит до двадцати последних операций внедрения с меткой времени и кратким описанием, позволяя вернуться к любому из предыдущих состояний обоих редакторов и результата одним кликом (полные снимки истории не переживают перезагрузку страницы — из localStorage восстанавливаются только заголовки записей без возможности откатиться к ним).

Валидация перед внедрением. Отдельная логика проверки запускается как явной кнопкой «Проверить», так и автоматически перед настоящим (не черновым) внедрением: проверяются пустота полей, совпадение определённого языка в обоих редакторах, языкоспецифичные проблемы кода (сбалансированность конструкций, анти-паттерны, потенциальные ошибки), наличие хотя бы одного распознанного блока в патче, дубликаты имён внутри патча, а также детальное сопоставление каждого блока патча с целевым блоком в исходнике — с предупреждениями о смене типа (процедура/функция), признака экспортности, директивы компиляции, состава параметров или области размещения для 1С, о смене вида объявления для JS или тега для HTML. Если обнаружены ошибки уровня "критично", попытка настоящего внедрения прерывается модальным окном со списком проблем и возможностью всё равно продолжить осознанно.

Проверки для каждого языка учитывают его специфику: для 1С — это анти-паттерн запроса внутри цикла, пустой или неинформативный блок Исключение, динамическое выполнение кода через Выполнить/Вычислить, конкатенация текста запроса вместо параметров, жёстко заданные GUID, отсутствие директив компиляции или описания у экспортных методов согласно стандарту ИТС #std453; для JavaScript — использование var вместо const/let, нестрогие сравнения, вызовы eval, присвоение innerHTML (риск XSS), забытые вызовы console.*, async-функции без await; для HTML — незакрытые теги, повторяющиеся id, изображения без alt, инлайновые обработчики событий, ссылки target="_blank" без rel="noopener", отсутствие атрибута lang; для CSS — несбалансированные скобки, дублирующиеся селекторы, избыточное использование !important, высокоспецифичные id-селекторы, чрезмерные значения z-index, глубоко вложенные селекторы и пустые правила.

Панель ИИ-ассистента. Выдвигающаяся справа панель (Ctrl+Shift+A) предлагает семь готовых сценариев работы с ИИ: объяснение последнего сравнения кода простыми словами, код-ревью патча с разделением на критичные ошибки/потенциальные проблемы/рекомендации, предложение сценариев тестирования для изменённых методов, идеи рефакторинга с примерами "было → стало", проверка соответствия языкоспецифичным стандартам (для 1С — именно стандартам разработки ИТС, для остальных языков — их аналогам), конвертация ключевых слов 1С между русским и английским вариантами синтаксиса, и автоматическое добавление документирующих комментариев к методам патча. Для каждого сценария формируется развёрнутый промпт с встроенным описанием контекста конкретного языка и его типичных требований. Панель поддерживает три режима подключения к модели: если инструмент открыт внутри среды, предоставляющей глобальный API для вызова ИИ (window.claude или window.genspark), запрос отправляется напрямую; если пользователь указал в настройках собственный HTTP-эндпоинт, совместимый с форматом Anthropic или OpenAI (с ключом API, который сохраняется только в localStorage браузера), запрос идёт туда; если ни то ни другое не настроено, инструмент работает в офлайн-режиме — просто показывает готовый текст промпта с кнопкой копирования, чтобы вставить его вручную в любой чат-интерфейс.

Автосохранение, история изменений и надёжность работы. Оба редактора, выбранный язык, тема оформления и последний результат внедрения автоматически сохраняются в localStorage браузера с небольшой задержкой после каждого изменения и восстанавливаются при повторном открытии страницы. Отдельно реализован полноценный стек отмены/повтора (до 50 шагов) для операций верхнего уровня — внедрения, удаления методов, вставки из буфера, обмена редакторов, замены текста — с указанием подписи операции во всплывающей подсказке кнопки «Отменить».

Режим «Создание проекта»
Второй крупный режим приложения — это конструктор структуры проекта, переключиться на который можно тем же переключателем в шапке. Он ориентирован на быстрый старт нового проекта или расширения по текстовому описанию его файловой структуры.

Ввод структуры. Левая панель содержит большое текстовое поле, куда можно вставить дерево каталогов в привычном псевдографическом виде (со значками ├── и └──), причём поддерживается как вставка одной только структуры имён файлов и папок, так и вставка целого ответа с деревом и с содержимым файлов под ним — в последнем случае файлы будут созданы уже с этим кодом внутри. Рядом с полем ввода расположен выбор языка (авто по расширению файла или явный выбор одного из четырёх языков), набор переключаемых опций генерации (добавлять докстринги/описания, добавлять TODO-метки, добавлять типизацию, добавлять блок лицензии в шапки файлов) и набор из восьми готовых быстрых шаблонов проектов — четыре под 1С (конфигурация, расширение, внешняя обработка, конфигурация с HTTP-сервисом) и четыре под веб (лендинг, SPA на JavaScript, набор веб-компонентов, форма), которые одним кликом подставляют в поле ввода готовую типовую структуру.

Дерево можно также импортировать из текстового файла (.txt/.md) кнопкой «Импорт» или сгенерировать через ИИ по свободному словесному описанию проекта, нажав кнопку «ИИ-генерация» — в этом случае используется тот же трёхуровневый механизм подключения к модели (среда/собственный эндпоинт/офлайн), что и в панели ИИ режима внедрения.

Дерево проекта. Центральная панель визуализирует введённую структуру как интерактивное дерево файлов и папок с иконками по типу, счётчиком файлов в шапке, кнопками разворачивания и сворачивания всех узлов сразу и статистикой по итоговому дереву. Клик по файлу открывает его во встроенном редакторе справа; для файлов дерева поддерживается контекстное меню по правому клику с быстрыми действиями, включая прямую отправку файла в режим внедрения.

Редактор файлов. Правая, самая крупная панель — это полноценный текстовый редактор с вкладками по открытым файлам (можно открыть сразу несколько файлов из дерева и переключаться между ними, закрывая вкладки по отдельности), собственной нумерацией строк и подсветкой активного файла. Для активного файла показывается его путь внутри дерева, размер и число строк, а также две ключевые кнопки интеграции с первым режимом: «Во Внедрение» (открывает этот файл как исходный код в редакторе внедрения) и «Как патч» (открывает его в правом, патч-редакторе внедрения) — то есть готовый файл из конструктора можно немедленно использовать как основу для дальнейшего внедрения точечных правок.

Сборка и экспорт. Кнопка «Создать проект» (Ctrl+B) генерирует содержимое всех файлов дерева на основе выбранных опций (докстрингов, TODO, типизации, лицензии) там, где содержимое не было предоставлено вручную во вставленном тексте. Кнопка «Скачать ZIP» упаковывает всю получившуюся структуру файлов и папок в один архив с индикатором прогресса генерации, что позволяет сразу получить готовый скелет проекта на диск.

Сквозные технические механизмы
Автоопределение языка. Если выбран режим "Автоопределение", инструмент анализирует текст по набору взвешенных признаков — для 1С это директивы компиляции, ключевые слова Процедура/Функция/КонецПроцедуры, операторы SQL-подобного языка запросов; для HTML — доктайп, теги html/div/script; для CSS — @-правила, синтаксис свойство: значение внутри скобок; для JavaScript — function, стрелочные функции, import/export, обращения к document/window — и выбирает язык с наибольшим суммарным весом признаков.

Разбор кода на единицы. Для каждого языка реализован собственный алгоритм разбора, учитывающий тонкости, которые обычный поиск по регулярным выражениям упускает: для 1С — многострочные сигнатуры, несколько подряд идущих директив и аннотаций перед заголовком, комментарий-описание, "слипшиеся" заголовки (когда КонецПроцедуры и следующая Процедура оказались на одной строке), принадлежность метода конкретной именованной области #Область, для последующей вставки новых методов именно туда, а не в конец файла; для JavaScript — классы и их отдельные методы (со статическими, геттерами/сеттерами и приватными полями), функции, присвоенные переменным через const/let/var в виде как обычных, так и стрелочных функций (в том числе с телом-выражением без блока), и методы объектных литералов верхнего уровня; для HTML — элементы с уникальным id, пользовательские теги с дефисом в имени, структурные секции типа head/body/main, а также рекурсивный разбор содержимого script и style как отдельных JS- и CSS-фрагментов с префиксацией имён; для CSS — произвольные селекторы любой сложности, вложенные контейнеры @media/@supports/@layer, атомарные блоки @keyframes/@font-face.

Приведение стиля и автоформатирование. При замене метода 1С инструмент определяет стиль отступов приёмника (табы или пробелы, и их ширина) и автоматически конвертирует к нему вставляемый блок, сохраняет отступ на позиции вставки, а также умеет переносить существующий комментарий-описание или директивы компиляции метода-приёмника, если патч их не содержит. После любой операции внедрения или удаления запускается автоформатирование, нормализующее пустые строки между методами, областями и директивами по правилам, специфичным для языка.

Подсветка синтаксиса. Собственный токенизатор на основе набора регулярных выражений для каждого языка раскрашивает ключевые слова, строки, комментарии, числа, типы, директивы, операторы и пунктуацию; для HTML отдельно распознаются и подсвечиваются вложенные фрагменты script и style соответствующими правилами JS и CSS.

Оформление интерфейса. Приложение построено в стиле стеклянного морфизма (glassmorphism) с полупрозрачными панелями, размытием фона и мягкими светящимися акцентами, поддерживает переключение между тёмной и светлой темой, а также содержит развитую систему всплывающих уведомлений (тостов) и модальных диалогов для подтверждения деструктивных операций.

Для чего это может быть полезно
Инструмент прежде всего адресован разработчикам 1С:Предприятие, которые регулярно получают от коллег, из чатов с ИИ-ассистентами или из внешних источников готовые фрагменты кода — переписанные процедуры, новые функции, исправления — и должны аккуратно встроить их в уже существующий, часто крупный модуль конфигурации или расширения, не потеряв директивы компиляции, комментарии-описания и правильное расположение по областям. Такая же логика полезна и веб-разработчикам, которым нужно внести точечные изменения в HTML-разметку, таблицу стилей CSS или JavaScript-модуль без ручного построчного сравнения файлов. Отдельная ценность инструмента — в сочетании с работой через больших языковых моделей: типичный сценарий — попросить ИИ-ассистента переписать конкретный метод или функцию, а затем вставить весь ответ модели целиком в правый редактор патча, доверив инструменту самостоятельно выделить нужный блок, сопоставить его с исходником и корректно заменить, одновременно получив diff, отчёт о рисках и метрики сложности для оценки качества правки. Второй режим конструктора проекта, в свою очередь, полезен на самом старте новой задачи или модуля — когда нужно быстро развернуть структуру каталогов и заготовки файлов по описанию или готовому шаблону, а затем немедленно перейти к точечному внесению правок в любой из созданных файлов через первый режим.
